# Windows Endpoint Deployment and Wazuh Agent Configuration

## 1. Purpose

This document records the preparation and integration of the Windows
endpoint into the Home SOC Lab. The endpoint forwards configured Windows
event data to the central Wazuh manager for monitoring and analysis.

## 2. Endpoint Environment

  Item                      Configuration
  ------------------------- ---------------------
  Virtual machine           `WIN11-01-Endpoint`
  Endpoint/agent name       `WIN11-01`
  Operating system          Windows 11 Pro
  Host-only address         `192.168.56.20`
  Wazuh manager             `192.168.56.10`
  Wazuh agent version       `4.14.10`
  Agent ID                  `001`
  Virtualisation platform   Oracle VirtualBox

The endpoint was configured with NAT for outbound connectivity and a
host-only adapter for communication with SOC01.

## 3. Wazuh Agent Deployment

The Wazuh agent was installed on the Windows 11 virtual machine and
registered with the Wazuh manager at `192.168.56.10`.

The registered agent was verified in the Wazuh agent inventory with the
following details:

  Field              Verified value
  ------------------ --------------------------
  Agent ID           `001`
  Agent name         `WIN11-01`
  Agent address      `192.168.56.20`
  Operating system   Microsoft Windows 11 Pro
  Wazuh version      `4.14.10`
  Status             `Active`

The Wazuh agent service can be checked from an elevated PowerShell
session:

``` powershell
Get-Service WazuhSvc
```

To restart the agent after a configuration change:

``` powershell
Restart-Service WazuhSvc
```

## 4. Sysmon Deployment

Microsoft Sysinternals Sysmon was installed on the Windows endpoint to
provide additional system telemetry, including process-creation events.

The Sysmon executable was extracted to:

``` text
C:\Tools\Sysmon
```

From an elevated PowerShell session, Sysmon was installed with:

``` powershell
cd C:\Tools\Sysmon
.\Sysmon64.exe -accepteula -i
```

The service state was checked with:

``` powershell
Get-Service Sysmon64
```

Sysmon event records were verified in the Windows Event Viewer channel
`Microsoft-Windows-Sysmon/Operational`.

For example, the following command retrieves recent process-creation
events (Event ID 1):

``` powershell
Get-WinEvent -FilterHashtable @{
    LogName = 'Microsoft-Windows-Sysmon/Operational'
    Id = 1
} -MaxEvents 10 | Format-List TimeCreated, Id, Message
```

## 5. Configure Wazuh to Collect Sysmon Events

The Windows Wazuh agent configuration file is:

``` text
C:\Program Files (x86)\ossec-agent\ossec.conf
```

The following `localfile` entry was added inside the existing
`<ossec_config>` element to collect the Sysmon Operational event
channel:

``` xml
<localfile>
  <location>Microsoft-Windows-Sysmon/Operational</location>
  <log_format>eventchannel</log_format>
</localfile>
```

The XML entry should appear only once. It must be placed inside the
existing root configuration element, not appended after the closing
`</ossec_config>` tag.

After saving the configuration, the Wazuh agent service was restarted:

``` powershell
Restart-Service WazuhSvc
```

## 6. Validate Event Collection

Local Sysmon event generation was first checked on the Windows endpoint.
The Wazuh manager was then checked to confirm that Sysmon-related event
data was being received.

The lab verification included process-creation telemetry with Sysmon
Event ID `1`. The event records included Windows event-channel
information and endpoint metadata.

A useful distinction during investigation is that not every event
received by Wazuh is necessarily a security alert. Events may be
collected and decoded without matching an alerting rule. The dashboard's
alert views display events that meet the configured alert criteria; they
are not automatically a complete record of every event generated by
Windows.

## 8. Troubleshooting Checks

If the endpoint is not reporting:

1.  Confirm that the Windows VM has the expected host-only address.

2.  Confirm that the Wazuh manager is running and reachable.

3.  Check the Wazuh agent service:

    ``` powershell
    Get-Service WazuhSvc
    ```

4.  Review the agent log, commonly located at:

    ``` text
    C:\Program Files (x86)\ossec-agent\ossec.log
    ```

5.  Confirm that the Sysmon service is running:

    ``` powershell
    Get-Service Sysmon64
    ```

6.  Confirm that Sysmon events exist in
    `Microsoft-Windows-Sysmon/Operational`.

7.  Check the agent configuration for valid XML and a correctly placed
    `localfile` entry.

8.  Restart the Wazuh agent after making a configuration change.

## 9. Security Considerations

The Windows endpoint was a dedicated virtual machine for lab exercises.
Testing should remain within the authorised lab environment. Do not
install lab monitoring agents or generate test activity on an everyday
personal host unless there is a separate, explicit reason and
appropriate safeguards.

Before publishing configuration files or event evidence, remove
credentials, personal information and sensitive host details.
